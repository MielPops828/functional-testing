## Задача T1. Написание тест-кейсов (GET /products/{productId}/status)

**Условие:**  
Реализован REST API для получения статуса продукта с параметрами recalculate, owner, region, а также обязательным токеном authToken. Требовалось составить план тестирования и набор проверяемых тест-кейсов.

**Артефакты:**
- [test-plan.md](test-plan.md) – план тестирования, включающий цели, объём, стратегию, параметры и их значения, попарные комбинации, критерии начала/завершения, риски.
- [test-cases.md](test-cases.md) – детализированные тест-кейсы (29 шт.) с предусловиями, шагами, ожидаемыми результатами, статусом и приоритетом.

---

## Задача T2. Написание баг-репортов (Яндекс.Диск UI и API)

**Условие:**  
Необходимо было протестировать требования и систему (UI поиска по файлам и папкам, API создания папки) и завести баг-репорты при обнаружении дефектов.

**Артефакты:**

**Рецензия требований:**
- [corrections-ui.md](corrections-ui.md) – анализ требований к UI поиска: выявлены неоднозначности (ограничение длины, обработка пробелов, Unicode, регистр, поведение для папок и корзины).
- [corrections-api.md](corrections-api.md) – анализ требований к API: указаны неясности (формат токена, допустимые значения fields, тело ответа при успехе, структура ошибок).

**Баг-репорты UI:**
- [ui-bug-report-1.md](ui-bug-report-1.md) – **Bug-Report-001**: поиск существующего файла с названием из спецсимволов приводит к отображению лишних файлов.
- [ui-bug-report-2.md](ui-bug-report-2.md) – **Bug-Report-002**: поиск по строке из спецсимволов возвращает все файлы, хотя ожидалось сообщение «Ничего не нашлось».

**Баг-репорты API:**
- [api-bug-report-1.md](api-bug-report-1.md) – **Bug-Report-001**: при попытке создать уже существующую папку ожидается код 401, фактически получен 409 (Conflict).
- [api-bug-report-2.md](api-bug-report-2.md) – **Bug-Report-002**: при успешном создании папки ожидается код 200, фактически получен 201 (Created); также не совпадает значение templated в ответе.

## Задача T3. Составление тест-плана (GET /products/{productId}/cost)

**Условие:**  
API для расчёта стоимости продукта с параметрами count и start, стоимость вычисляется нарастающим итогом по таблице, партиями по 5 единиц. Токен обязателен.

**Артефакты:**
- [api-test-plan.md](api-test-plan.md) – план тестирования: цели, объём, подход, параметры и техники (граничные значения, таблица принятия решений, попарное тестирование), критерии, риски, приложения с таблицами.
- [api-test-cases.md](api-test-cases.md) – тест-кейсы (15 шт.), включая позитивные и негативные сценарии, параметризованный тест с таблицей ожидаемых стоимостей для различных комбинаций count и start.

## Задача T4. Составление плана тестирования (Сервис А и Сервис В)

**Условие:**  
Сервис А принимает REST-запросы на управление услугой, отправляет AMQP-команды сервису В, обеспечивая упорядочивание и ожидание ответа перед следующей командой. Статус услуги изменяется только после положительного ответа от В.

**Артефакты:**
- [services-test-plan.md](services-test-plan.md) – план тестирования: объект, объём, подход, критерии начала/приостановки/завершения, среда, роли, сроки, риски.
- [services-test-cases.md](services-test-cases.md) – тест-кейсы (11 шт.), проверяющие успешные операции (подключение, отключение, блокировка), асинхронность, порядок команд, обработку ошибок, таймауты, дублирование и потерю сообщений.
