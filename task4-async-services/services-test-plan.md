# Идентификатор тест-плана: TP-ASYNC-SERVICES-001
#### Версия: 1.0
#### Дата создания: 27.04.2026
#### Автор: QA Engineer
### Объект тестирования:
- REST API сервиса A:
    - подключение услуги
    - отключение услуги
    - блокирование услуги
- взаимодействие сервиса A и сервиса B через брокер RabbitMQ
- обработка асинхронных ответов от сервиса B;
- порядок выполнения команд;
- версия сборки: build v1.0.0
### Объем тестирования:
- В область тестирования входят:
    - валидация REST-запросов сервиса A;
    - отправка AMQP сообщений в очередь;
    - получение и обработка ответов от сервиса B;
    - соблюдение порядка выполнения команд;
    - бизнес-логика изменения статуса услуги;
    - асинхронная обработка запросов;
    - обработка ошибок (сервис B недоступен, ошибка ответа);
    - устойчивость к дублированию и потере сообщений;
- В область тестирования не входят:
	- UI;
	- база данных;
	- производительность и нагрузка;
	- внутренняя реализация сервисов A и B.
### Подход к тестированию:
- типы тестирования: функциональное тестирование, интеграционное тестирование;
- уровни тестирования: системное тестирование;
- методы тестирования: эквивалентное разбиение, исследовательское тестирование;
- инструменты: Postman, Swagger, RabbitMQ Management UI
### Критерии начала тестирования:
- сервис A доступен по REST;
- сервис B доступен;
- брокер RabbitMQ развернут и доступен;
- документация API утверждена;
- подготовлены тестовые данные;
### Критерии приостановки тестирования:
- недоступен сервис A, B или RabbitMQ;
- Blocker и/или Critical баги;
- невозможность отправки или получения сообщений;
### Критерии возобновления тестирования:
- сервисы восстановлены;
- очередь доступна;
- Blocker и/или Critical баги исправлены;
### Критерии завершения тестирования:
- все запланированные тест-кейсы выполнены;
- все дефекты с приоритетом Blocker и Critical закрыты;
- составлен итоговый отчет.
### Среда тестирования:
- ОС: Windows 11 25H2, macOS Tahoe 26.4, Ubuntu 22.04;
- Инструменты: Postman v12.7.6, Swagger v5.32.1, RabbitMQ v4.3.0 (Management UI)
### Тестовые артефакты:
- тест-кейсы;
- чек-листы;
- баг-репорты;
- отчет о тестировании;
- логи сообщений (RabbitMQ);
- логи выполнения тестов;
### Тестовые данные:
- операции connect/disconnect/block;
- последовательности запросов;
- дублирующиеся запросы;
- задержанные и некорректные ответы от сервиса B;

### Риски и меры реагирования:
- недоступность RabbitMQ:
	1. уведомить DevOps;
	2. зафиксировать блокер;
	3. приостановить тестирование;
- болезнь или недоступность сотрудника:
	1. перераспределить задачи внутри команды;
	2. обновить сроки;
	3. приоритизировать критические тесты;
- нарушение порядка очереди:
    - зафиксировать дефект;
    - приложить логи очереди;
    - воспроизвести сценарий;
- потеря сообщений:
    - проверить настройки очереди;
    - зафиксировать дефект;
    - добавить повторные проверки;
- недоступность сервиса B:
    - зафиксировать;
    - проверить retry/таймауты;
- отсутствие документации:
	1. произвести уточнение требований;
	2. зафиксировать допущения в тест-плане;
	3. произвести исследовательское тестирование;
