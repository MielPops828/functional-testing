Название проекта: Тестирование REST API GET /products/{productId}/cost?authToken=&count=&start=
Цели исследования:
- проверить соответствие API спецификации:
	- HTTP-коды (200, 401, 404, 500);
	- формат JSON-ответов;
    - правильность расчета стоимости.
- проверить валидацию входных параметров:
	- длина и формат authToken;
	- допустимые значения параметров count и start;
- проверить бизнес-логику:
    - расчет стоимости с нарастающим итогом;
    - корректность применения таблицы стоимости;
    - обработку партий (>5);
- проверить обработку ошибок:
	- отсутствие токена;
	- несуществующий productId;
	- внутренние ошибки сервера;
Объем тестирования:
- В область тестирования входят:
	- параметры (authToken, productId, count, start);
	- http-коды (200, 401, 404, 500);
    - бизнес-логика расчета стоимости;
	- json-ответы ({ "cost": number }, { "errorMessage": "..." })/
- В область тестирования не входят:
	- UI;
	- база данных;
	- внутренняя реализация бизнес-логики.
Типы тестирования: функциональное тестирование;
Подход и стратегия:
- ручное тестирование (Postman, Swagger);
- тестирование по тест-кейсам;
- исследовательское тестирование: использование невалидных значений параметров, случайная комбинация параметров.
Параметры и их значения:

| Параметр    | Валидные значения              | Невалидные значения          | Техники               						   	|
| ----------- | ------------------------------ | ---------------------------- | ------------------------------------------------|
| authToken   | 16 символов (буквы+цифры)      | <16, >16, спецсимволы, пусто | граничные значения, эквивалентное разбиение   	|
| productId   | существующий ID                | несуществующий, строка, null | эквивалентное разбиение       				   	|
| count       | 1-5, >5 (обработка партиями)   | 0, <0, строка, null          | граничные значения, попарное тестирование 	    |
| start       | 0-4                            | <0, строка, null             | граничные значения, попарное тестирование 	    |

Роли и зоны ответственности:
- QA Engineer - написание тест-кейсов, выполнение тестов;
- QA Lead - планирование, ревью;
- Developer - исправление багов/дефектов;
- Product Owner - уточнение требований.
Среда тестирования:
- ОС: Windows, macOS, Linux;
- Инструменты: Postman, Swagger
Тестовые данные:
- валидный и несуществующий productId;
- валидный (16 символов) и невалидный токены authToken (больше 16 символов, меньше 16 символов);
- валидные, невалидные, граничные, отсутствующие значения параметров start и count;
Сроки:
- анализ требований: 1 день;
- планирование: 1 день;
- выбор тестового окружений: 1 день;
- написание тест-кейсов: 1-2 дня;
- настройка тестового окружения: 1 день;
- тестирование: 2 дня;
- завершение тестирования: 1 день;
Риски и меры реагирования:
- недоступность тестового стенда:
	1. уведомить команду (QA Lead, Dev);
	2. зафиксировать блокер;
	3. приостановить тестирование;
	4. переключиться на актуализацию кейсов;
- болезнь или недоступность сотрудника:
	1. перераспределить задачи внутри команды;
	2. обновить сроки;
	3. приоритизировать критические тесты;
- неопределенное поведение при невалидных параметрах:
	1. зафиксировать поведение как дефект;
	2. уточнить требования у Product Owner;
	3. обновить тест-кейсы после прояснения;
- ошибки в расчетах:
    1. задокументировать кейс;
    2. добавить дополнительные проверки;
- отсутствие документации:
	1. произвести уточнение требований;
	2. зафиксировать допущения в тест-плане;
	3. произвести исследовательское тестирование;
Критерии начала тестирования:
- API доступен;
- есть документация;
- есть тестовые данные;
Критерии приостановки тестирования:
- API недоступен;
- Blocker и/или Critical баги;
Критерии возобновления тестирования:
- API восстановлен;
- Blocker и/или Critical баги исправлены;
Критерии завершения тестирования:
- все тест-кейсы выполнены успешно;
- исправлены баги Blocker и Critical;
- задокументированы баги.
