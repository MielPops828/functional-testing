# Рецензирование требований (API)

## Условие задачи:
- Реализовано REST API PUT https://cloud-api.yandex.net:443/v1/disk/resources
- с заголовками Content-Type: application/json, Authorization: [token]
- параметры строки запроса: 
    - path - Путь к создаваемой папке, 
    - fields - Список возвращаемых атрибутов
- В случае успешного выполнения запроса получен ответ 200, папка появилась по нужному адресу в диске
- Если какие-то данные некорректны - ответ 400
- При неверном или отсутствующем токене - ответ 401
- При попытке создания уже по существующему пути - ответ 400
- При возврате ответа от сервера отличному от 200 - папка создана не была, получено тело ответа следующего вида:
{ "message": "string", "description": "string", "error": "string" }

- что считается некорректными данными?
- не указан формат токена;
- для PUT операций обычно используется ответ 201 (Created);
- какие значения параметра fields допустимы?
- что возвращается, если параметр fields не указан?
- все ли ошибки возвращают одинаковую структуру json-ответа?
- требования не содержат уникальных идентификаторов, что затрудняет трассируемость между требованиями, тест-кейсами и баг-репортами;
- какое тело ответа возвращается при успешном запросе (200)?
- неявно описано тело ответа для ошибок (не указано, для каких кодов оно возвращается).
